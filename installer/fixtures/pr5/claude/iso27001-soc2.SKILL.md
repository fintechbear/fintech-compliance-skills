# Skill: ISO 27001 & SOC 2 (Security Controls)

**Load for code that must meet an information-security control framework.**

## When to use

Building systems that handle sensitive data and are (or will be) audited against
ISO/IEC 27001 or SOC 2 (Security, Availability, Confidentiality).

## Do

- **Access control:** role-based, least privilege, deny by default.
- **Encryption:** in transit (TLS 1.2+) and at rest; keys in a KMS.
- **Logging & monitoring:** record security events (auth, access, config change)
  to tamper-evident, append-only storage.
- **Change management:** code reviewed and traceable to an approved change.
- **Secrets management:** from a vault, rotated, never in code or logs.
- **Data retention & deletion:** honor defined retention; support secure deletion.
- **Backups:** encrypted, tested restore path.

## Never (red lines)

- Never grant blanket admin access "to make it work."
- Never disable or route around audit/security logging.
- Never ship secrets in source or build artifacts.

## Good example

```python
@require_role("payments.reader")       # least privilege, deny by default
def read_statement(account_id):
    audit.record(actor=current_user, action="read_statement", account=account_id)
    return statements.get(account_id)
```

## Bad example

```python
# ❌ no authz, no audit, admin-for-everyone
def read_statement(account_id):
    return statements.get(account_id)
```
