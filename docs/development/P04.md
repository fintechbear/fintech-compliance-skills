## 2. On-demand loading / content architecture

- Shared rules live once (refusal policy + `controls/catalog.json`); the transfer skill
  references them by FCS id instead of duplicating them.
- The skill explicitly tells the agent to READ `languages/<lang>.md`, `databases/<db>.md`
  and the region file when the task touches them — it does not assume they are loaded.
- Explicit `name`/`description` metadata, not derived from the first bold run (the old
  installer behaviour, which P04 flags as an anti-pattern).

## 3. PostgreSQL-correct, not SQL Server

The `.NET` skill text shows a SQL Server `rowversion` token. The TS reference uses
PostgreSQL-correct mechanisms and the README states the distinction: explicit integer
`version` column for optimistic concurrency, `SQLSTATE 23505` for unique-key dedup,
`SERIALIZABLE` + `40001` retry for serialization failures.

## 5. Debugging done (honest trail)

The TS harness needed four fix passes, each a real bug found by running it, not a
rubber-stamp: (a) skill links had to be written in SOURCE form so the installer rewrites
them (`../group/file.md`, not pre-rewritten `../X/SKILL.md`); (b) `npm ci` needs a
committed lockfile — runners fall back to `npm install` (package.json is exact-pinned);
(c) `pg` is CommonJS, so ESM needs `import pg from 'pg'; const { Pool } = pg`;
(d) two scenarios passed numbers where `fresh()` expects tenant/currency. After (d):
17/17.
