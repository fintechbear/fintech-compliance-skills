## 2. Key safety properties proved (real DB)

- **UnknownOutcome is not auto-failed**: a provider timeout leaves state `pending_unknown`; a
  safe retry reuses the SAME idempotency key and resolves to one charge — no blind re-charge
  with a new key (FCS-OUTCOME-001 / FCS-IDEMP-001 / FCS-OUTBOX-001).
- **Webhook signature on raw bytes**: a tampered body fails verification; a stale timestamp is
  rejected; a re-delivered event id is a durable-dedup no-op (FCS-WEBHOOK-001).
- **Ledger**: unbalanced posting rejected; duplicate business_ref rejected; a correction is a
  reversal entry (original stays visible); currencies never summed (FCS-LEDGER-001).
- **Reconciliation** classifies ok/missing/duplicate/amount/currency and **moves no money**
  (balances unchanged by running it) (FCS-RECON-001).
